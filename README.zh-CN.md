# 四边形 UV 修复 / Quad UV Fix

**作者：BenzWood · MIT 开源 · 0.3.0 beta · Blockbench 5.2+**

解决梯形 Mesh 四边形面搭配矩形 UV 时，像素格在内部三角形对角线附近突然折弯的问题。同步处理贴图预览、像素辅助线和绘画定位，无需细分模型。

编辑时使用四角映射。**原生 glTF/GLB、FBX、OBJ 的完整模型导出默认自动烘焙**，临时副本编译后恢复原工程，直接保存导出模型。补偿 PNG 用有限分辨率近似保存修复效果，不要求引擎增加专用 Shader。关闭“原生模型导出自动烘焙”开关后才沿用未修复的原生导出。

## 三步上手

1. 下载 [benz_quad_uv.js](https://raw.githubusercontent.com/BenzWood/blockbench-quad-uv-fix/main/benz_quad_uv.js)，在 Blockbench **文件 → 插件 → 从文件加载插件**中选择它。
2. 切到普通纹理视图，选中 Mesh。只想处理部分面时，进入面选择模式并选中目标面。
3. 点击 **工具 → 四边形 UV 修复 → 启用选中面的修复**，继续按原来的方式绘画。

不需要填“5×21”等格子数量，格线按贴图实际像素间距计算。格子的宽度仍随梯形宽度自然变化，不能让不同宽度的上下边都拥有完全一样大的正方形。

对象模式处理选中 Mesh 的有效四边形面；面模式只处理明确选中的面。锁定 Mesh 跳过。格线是否可见沿用 Blockbench 的 Pixel Grid / Painting Grid 设置。

## 常用操作

- **修复预览**：开关对比原来的映射，保留启用标记。
- **取消选中面的修复**：取消目标面的标记，支持撤销/重做。
- **使用说明与当前状态**：显示已标记面数与当前实际修复面数。切到不支持的视图、使用不兼容材质或几何退化时，两个数字可能不同。
- 保存 `.bbmodel` 时保持插件已加载。没有插件时打开并重新保存，未知面标记可能丢失；标准模型与 UV 仍保留。

已经切成许多长条的面不会自动合并。想对整块梯形做四角映射，需要先恢复希望保留的原面。

## 直接烘焙导出游戏模型

1. 在原工程完成绘画，切到编辑或绘画模式。
2. 按原来的 **文件 → 导出 → glTF/GLB、FBX 或 OBJ** 操作。“工具 → 四边形 UV 修复 → 原生模型导出自动烘焙”默认开启；也有“烘焙并直接导出 GLB/glTF”快捷入口。
3. 倍率选 **自动**，精度选择 **1/16（默认）** 或 **1/32**。每张受影响贴图从 1× 到 64× 按整数逐级评估，在尺寸预算内选择首个满足采样目标的倍率。精度是估计，不是严格误差保证。
4. 可选 **边缘抗锯齿**：只在检测到颜色边界的输出像素进行 4×4 覆盖采样，按透明度混合边界颜色；大片纯色保留。保持纯调色板硬像素时关闭它，仅提高精度。抗锯齿也不能让有限图片在所有视角/缩放下严格零误差。
5. 在同一个窗口选择原生导出的比例、动画、编码等选项，保存模型即可。GLB/glTF 自动内嵌贴图；桌面 FBX/OBJ 自动把 PNG 保存到模型旁，OBJ 同时保存 MTL，还有 `.quad-uv-report.json`。不再需要解压、打开副本、再次导出。
6. 游戏使用导出的模型与补偿贴图。核对 Point/Nearest、最大导入尺寸、压缩及 Mipmaps，避免引擎导入时重新缩小高精度贴图。

**ZIP 仅用于检查或备份：**工具菜单仍提供“导出烘焙副本 ZIP”，可打开其中的 bbmodel 检查。网页端 GLB/glTF 直接下载；FBX/OBJ 多文件仍打包为 ZIP。原生集合/部分导出和直接调用 `compile()` 的第三方导出器沿用自身流程，未自动接管。

原工程继续用于绘画，改图后重新烘焙。不会把补偿图写回原纹理，不会改 Unity/Godot 的 Shader、材质资产或项目配置。副本中受影响贴图的图层被合并，面修复标记被移除，避免二次修复。

**固定三角化：**副本将目标四边形明确写为原来的两个三角面，复用原位置顶点键；遇到共享 UV 冲突时调整副本 UV，不加新位置顶点或渲染三角形；编辑器面数会增加。矩形 UV 岛仍为矩形，但在副本中可能缩放或平移。不同导出器仍可能因 UV/法线边界拆分渲染顶点，不能保证所有格式导入后的顶点计数完全一致。轻微不共面时，三角化后的法线也需核对。

**倍率不是默认越大越好。**算法比较输出像素中心与四角处的颜色及映射位移，目标可选 1/4、1/8、1/16（默认）或 1/32 原像素。它是基于采样的误差估计，不是严格误差上界，也不是 Unity/Godot 已验收结果；只保证从候选倍率里选择首个通过估计的值。实际选择、大小和误差写入 `bake-report.json`。

首版支持静态贴图和范围内 UV。共享 UV 需要不同颜色时，会自动把冲突面分配到同一张补偿图集中的独立区域；兼容的重叠保留，相同补偿区域复用。扩展图集时同步换算使用该图集的副本 UV，原工程 UV 保留。区域按面裁剪、添加两输出像素边距，并采用紧凑排布，不保证数学意义的最小图集；最终尺寸以报告为准。单张输出最多 1600 万像素、单边 4096，总受影响输出最多 6400 万像素；处理时可取消。

## 可以处理什么？

面和 UV 的有效投影都必须是凸四边形。典型用途是梯形腿、斜面、渐缩杆体等搭配规则矩形 UV 的像素画。支持普通纹理与 UV 棋盘视图，矩形 UV 的平移、镜像与旋转。

编辑预览不会增加模型顶点/面，不会重新排 UV，不会模糊贴图。只增加面启用标记、临时渲染属性和辅助线，仍有 GPU、内存与格线生成开销。

这里的“双线性映射”不是纹理 Bilinear 过滤。算法让四条边上的 UV 按相同比例分布，并消除原内部对角线的映射突变；斜向图案可能弯曲。

## 当前限制和验收状态

- PBR/Material、法线、线框等视图沿用原效果。
- 凹面、三角形和退化面跳过；明显扭曲、不共面或极狭长的面存在几何与数值边界。
- 大笔刷的光标轮廓是局部近似；跨面接缝不会自动缝合；其他预览/绘画插件可能冲突。
- 关闭自动烘焙后的原生导出没有插件映射；烘焙导出用普通贴图近似，需核对采样与导出效果。

首版预览已获得作者当前梯形腿案例的有效反馈。0.3.0 增加直接导出、1/16 与 1/32 精度、可选边缘抗锯齿及 glTF 防缩放；直接导出和新精度功能、此前菜单与选择保护改动，以及动画、镜像、透明纹理、多项目、网页端、导出等组合由使用者验收，不宣称全部验证。
